# ユーザーフローと動線の設計

公開サイトの設計メモ。読者の入口ごとに「次に何をしたいか」を置き、各画面がその一手を支えているかを点検するための基準にする。

## 前提

- 読者は、AI の導入や組織設計に関わる経営者・企画職と、論文を調べる研究者
- 着地の大半は検索と X からの記事ページで、ホームから入る人は少ない
- 記事は AI が論文をもとに書いており、査読を経ていない。読者が出典で裏づけられる導線が信頼の前提になる
- 計測はまだ無いので、以下は推論による仮説。GA4 を入れたら、流入元別の次の遷移で検証する

## 仕分けの目的(画面に出す一文)

> 論文を「AI 時代にも通用する知識か」で仕分けして、読む順番と記事化の優先度を決めています。

| 分類 | 印 | 読み手にとっての意味 |
|---|---|---|
| 不変原理 | ◆ | 最初に読む。時代や対象が替わっても成り立つ構造 |
| 設計原理 | ◇ | 次に読む。いまの制約を前提にした設計の指針 |
| 参考 | ▫ | 必要なときに引く。条件に依存する個別の知見 |

出す場所: ホームの「読む順番は、仕分けで決まります」、読み方ガイド、記事冒頭の分類ピル、一覧の見出し直下、アトラスの絞り込み、各分類の印のホバー説明。文言は `config/site.yaml` の `tiers` が唯一の出どころ。

## 入口ごとのフロー

### A. 検索から記事へ(最多)

1. 知りたいこと: この記事は自分の疑問に答えるか。3 秒で決めたい
   - 支える設計: 冒頭の 1 文要約、実務への含意、分類ピル(定義つき)
2. 読み進める: 全体像と現在地を知りたい
   - 支える設計: 目次(現在地連動)、進捗バー、本文中の用語リンクのホバープレビュー
3. 読み終える直前: 次に何を読むか決めたい
   - 支える設計: 読了間際に出る「次に読む」バー(未読を優先)
4. 読み終えた後に選ぶ道は 5 つ
   - 基礎へ戻る(この記事が参照する概念)
   - 応用へ進む(この記事を参照する概念)
   - 設計に落とす、または原理に戻る(分類をまたぐ)
   - 別の領域の見方(領域をまたぐ)
   - 裏づける(出典の書誌から原典へ)
5. 離脱の手前: 保存と共有
   - 支える設計: X でポスト、リンクのコピー、既読の記録

### B. X から記事へ

Aと同じだが、サイトの文脈を持たない。冒頭の分類ピルと「読み方」の導線で、不変原理から読むという前提を伝える。

### C. ホームから

1. 何のサイトか: ヒーローの見出しと 1 段落
2. 自分に関係する入口: 領域の一覧(問いつき)
3. 迷ったら: 不変原理のカード、「不変原理から読む」ボタン
4. 仕分けの理由: ホームの「読む順番」の節
5. 探索したい: アトラス

### D. 再訪

- ホームの「続きから」(最後に読んだ記事)
- 検索を開くと「最近読んだ記事」と「迷ったら、不変原理から」
- 一覧・カードの既読表示で、未読を探す

既読はブラウザの localStorage にだけ保存する。外部へは送らない。

### E. 調べもの(研究者)

- 一覧の絞り込み(領域・分類・語)を URL に反映し、共有できるようにする
- 出典の書誌(著者・年・DOI)と原稿へのリンク
- 領域ページの「読む順番」と、隣の領域への橋渡し

## 画面ごとの「次の一手」

| 画面 | 主な次の一手 | 副次の一手 |
|---|---|---|
| ホーム | 領域を選ぶ / 不変原理から読む | 続きから、新着、アトラス、読み方 |
| 記事 | 次に読む(バーと末尾の主カード) | 基礎・応用・設計・別領域、領域一覧、アトラス、検索 |
| 領域ページ | ① 不変原理の 3 本 | ② 設計原理の 3 本、分野への移動、隣の領域 |
| 記事索引 | 絞り込んで読む | 分類の説明、読み方ガイド |
| 読み方ガイド | 不変原理から読む | 設計原理、参考、領域を選ぶ |
| アトラス | 点を選んで記事を読む | 分類・領域で絞る |
| 検索 | 結果を開く | 空の状態では最近読んだ記事と不変原理 |
| 404 | 不変原理から読む | 記事索引、検索 |

## 既知の限界

- 記事の分類は、出典論文の判定のうち最も不変な側を引き継いでいる。公開時点で全記事の約 7 割が不変原理に入るため、分類だけでは優先度の差が小さい。画面では「参照の多い順」を併用している
- 「基礎へ戻る」「応用へ進む」は、記事どうしの参照の向きから作っている。内容上の前提関係を保証するものではない
- 記事本文中の未解決の用語リンク(記事が無い概念)は、リンクにしていない

## 審査の記録(2026-10-02)

独立レビュワー 2 体(Opus: 読者の行動の視点、Fable: 情報設計と視覚の視点)に、スクリーンショットと実装を渡して 3 ラウンド審査した。合格条件は、総合 7.5 以上かつ重大な指摘 0 件。

| ラウンド | Opus | Fable | 主な修正 |
|---|---|---|---|
| 1 | 6.0 | 5.8 | 記事末尾の列名が内容と食い違う、モバイルで仕分けの説明が届かない、末尾の選択肢が多すぎる |
| 2 | 7.1 | 7.1 | 分類の印を同寸の描画に統一、列名・案内文を 1 か所の定義(`NEXT_LABEL`)に集約、読了間際のバーが出ない |
| 3 | 7.6(合格) | 7.8(合格) | 本文の終わりに「次に読む」を置く、主カードの語尾を揃える |

残っている軽微な点: アトラスの「複雑系」のラベルが点の塊から離れる、ガイドの「六つの領域」とホームの節名の一致を機械的に保証していない、領域またぎの列と参照の向きの列が直交している。
