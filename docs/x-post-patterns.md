# X 投稿の型（13 アカウントの読み取りから）

作成日: 2026-11-25。Chrome で各アカウントのプロフィールの「Posts」を開き、直近の投稿を読み取って分類したものです。

目指すアカウント像: 論文の技術的本質・図解・実装検証に徹し、インフルエンサー的な雑音や経営・広報のアナウンスが少ないアカウント。

## 読み取りの範囲と限界

- 1 アカウントあたり、画面に出た直近の 4〜7 件だけです。投稿の反応数は系統的に取っていません
- Gwern は投稿が取れませんでした（表示が空）。鈴木 雅大は直近が学会の告知と人事の報告で、型の材料になりませんでした
- 投稿者の知名度（岡野原さんは 4.1 万フォロワー）が違うため、反応の大きさは型の良し悪しの証拠になりません。ここでは「何を書き、何を書かないか」だけを取り出しています

## 1. 目指す像に合う書き方（取り入れる）

| 型 | 見本 | 書き方 |
|---|---|---|
| A. 論文の核心 | 岡野原 大輔、DAIR.AI | 1 本目に「何をどうして何を実現する手法か」を 1〜2 文で言い切る。2 本目（または引用・カード）に論文の題名と出典を置く |
| B. 図解 1 枚 | Sebastian Raschka、Cameron Wolfe | 主張を 1 文で書き、図を 1 枚付ける。図の読み方は本文に 1〜2 行で足す |
| C. 概念の区別 | Cameron Wolfe | 混同されやすい 2 つの量を分けて定義する（例: 能力と信頼性、後者を測る指標 pass^k）。定義を先に書く |
| D. 実装検証 | Andrej Karpathy、Maxime Labonne | 試した条件・規模・所要時間を数字で書く（「4,300 万件を 6,454 件に絞った」「2 時間」）。結果は動いたことと動かなかったことを両方書く |
| E. 体系まとめの予告 | Lilian Weng | 長文は本体に置き、投稿には「何を扱い、何を答えているか」だけを書く |

### A 型の分解（最も参考になった 2 本構成）

岡野原さんの投稿は、ほぼ次の形でした。

1. 1 本目: 「[手法]は、[仕組み]によって[達成するもの]を実現する手法である。今回は[新しい点]を加え、[結果]を達成している。」
2. 2 本目: 英語の題名とリンクだけ。評価語（すごい・画期的）を足さない

最小全域木の投稿は「決定論的に線形時間で求めるアルゴリズムが、AI を活用した研究によって発見された」と、事実だけで始めていました。この投稿が画面上で最も反応が大きく、閲覧は約 1 万、リポストは 38 でした。

DAIR.AI は、同じ型に「なぜ重要か」を 1 文足します。「この研究は[誰]にとって重要である」「同じ学習計算量で、[条件]のとき[数字]」の順です。

## 2. 取り入れない書き方（避ける）

| 避けるもの | 見本 | 理由 |
|---|---|---|
| 製品・機能の発表の羅列、絵文字の箇条書き、料金 | Philipp Schmid | 目指す像の「広報アナウンス」にそのまま当たる |
| 採用募集、イベント・学会の告知、人事の報告 | 岡野原（固定投稿）、鈴木 雅大、Lilian Weng | 論文の本質から離れる |
| 祝辞、冗談、1 行の反応、天気の話のような挨拶 | Nathan Lambert、Maxime Labonne、Sebastian Raschka | 後から読む価値が残らない |
| 論争への参加、業界の勝ち負けの予想 | Lucas Beyer、Sebastian Raschka | 意見の投稿で、検証できる主張になっていない |
| 「保存推奨」「ブックマークして」 | DAIR.AI | 読者へのお願いで、内容ではない |
| 論文の題名とリンクだけを流す | AK | 速報としては成立するが、本質が書かれていない |

## 3. 自分のアカウントの型（案）

researcher の記事の欄に対応させています。

| 型 | 1 本目に書くこと | 材料にする欄 | 添えるもの |
|---|---|---|---|
| A. 論文の核心 | 手法・仕組み・実現することを 1〜2 文 | wiki 記事の要約、`key_insight` | 論文の題名と出典を 2 本目に |
| A+. 含意つき | A の後に「だから何が変わるか」を 1 文 | 記事の含意（現在は空の記事が多い） | なし |
| B. 図解 1 枚 | 主張 1 文＋図 | 記事の mechanisms から図を起こす | 図の読み方 1〜2 行 |
| C. 概念の区別 | 2 つの量の定義と、区別が効く場面 | 記事の概念定義 | 区別を測る指標があればその名前 |
| D. 実装検証 | 条件・規模・所要時間・結果 | 手元で動かした記録 | 動かなかった点を 1 行 |

### 文体と形式の決まり

1. 文末は「〜です」「〜ます」の敬体にする（2026-11-25 決定。見本の岡野原さんは常体だが、文の構造は敬体でも同じ）
2. 評価語（革新的・衝撃・必見）を使わない。数字・条件・限界で語る
3. 1 本目に結論を書く。リンクは 2 本目か返信に置く
4. 論文の原典を読んでいない数字は書かない。記事の要約だけが根拠のときは「要約に基づく」と添える
5. 限界・未検証の点を 1 行入れる（型 A・D は必須）
6. 製品名・会社名の発表、募集、告知、祝辞、冗談は投稿しない

### 書き出しの雛形

```
[手法・概念]は、[仕組み]によって[実現するもの]を可能にします。
従来は[前提]でしたが、[新しい点]により[結果・数字(条件)]です。
限界: [未検証の点]です。
```

2 本目: `[英語の題名]` と論文リンク。

## 4. 図の様式（2026-11-26 決定）

図は、端末（CLI）の画面の様式で作ります。学術調・イラスト調・3D ポップ・グラス・落ち着いた立体を描き比べ、この様式に決めました（比較した図は `docs/x-posts/2026-11-25/variants/`）。

部品と色は [terminal_style.py](x-posts/terminal_style.py) にまとめてあり、新しい図はこれを import して作ります。実例は [build_terminal.py](x-posts/2026-11-25/build_terminal.py) です。

### 見た目の決まり

| 要素 | 決まり |
|---|---|
| 地 | 黒に近い無彩色 `#141517`。真っ黒と、色味のある暗色は使わない |
| 文字 | 等幅（SF Mono）。和文は Hiragino Sans |
| 色 | 青緑 `#6FB7AC` の 1 色と無彩色だけ。青緑は、その図で言いたい 1 か所（結論・注目の値・媒介の経路）に置く |
| 線 | 1〜1.5px。折るときは直角。矢じりは開いた「>」の形 |
| 箱 | 1px の罫線と角 8px。影・光沢・グラデーション・アイコンは使わない |
| 量 | ブロック文字の棒（9px の塊と 3px の隙間）で描く |
| 記号 | 見出しは「> 」、副題と注記の見出しは「# 」、操作の見出しは「$ 」で始める。箱には変数名（x・m・y）を付けてよい |
| 寸法 | 1200×675、出力は 2 倍の解像度。左右の余白 72px |

### 配置の決まり

- 本体（副題と出典のあいだ）は、上下の余白を揃える。差は 12px 以内
- 揃えるときは、先に中身（行の間隔・棒の太さ・文字）を縦に広げて空きを減らし、残った差を位置で揃える。位置だけで揃えると、中身が小さいまま上下に空きが分かれる
- `render()` が書き出しのたびに上下の余白と横のはみ出しを測り、外れた図に `WARN` を出す。`WARN` が残ったまま出さない
- 書き出した PNG は必ず目で見る（文字と線の重なりは、測定では見つからない）

## 5. 未決の点

2. 図解（型 B）は、手で作るか、記事から自動で起こすかを決めていません
