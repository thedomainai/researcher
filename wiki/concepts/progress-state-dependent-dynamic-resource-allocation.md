# 進捗状態依存の動的資源配分

多段階タスクを遂行するシステムでは、各ステップで残りのタスクの難易度やコスト制約、進捗の良し悪しが絶えず変化する。このため、タスク開始時点で資源配分を一括決定する静的なアプローチは構造的に不十分であり、進捗状態を継続的に評価しながらエージェントや計算量を動的に再配分する仕組みが必要になる。これはマルチエージェント LLM ワークフローのような AI Native システムにおいて、品質を保ちつつコストを制御するための根本的な設計制約である。

## 概要

進捗状態依存の動的資源配分とは、タスク実行の各ステップにおいて「どの程度進んだか」「残タスクはどの程度難しいか」「コスト・時間予算にどれだけ余裕があるか」という状態変数を観測し、それに応じて次に投入する資源(エージェントの種類、計算量など)を逐次的に決定する制御メカニズムを指す。一度きりのクエリレベルの判断ではなく、ワークフローが進行する中で状態が変化することを前提にルーティングを更新し続ける点が核心である。

## 理論的背景と知見

この概念の中心的な知見は ProgRouter の研究(2026年)から得られる。ProgRouter は、専門化された LLM エージェント間の協調推論によって複雑で開放的なタスクを解くマルチエージェント LLM ワークフローを対象とし、繰り返される LLM 呼び出しと長期コンテキストの蓄積によって運用コストが膨らむという問題に取り組んでいる。

この研究は、既存のカスケードルーティング手法が「ワンショット・クエリレベル」の決定しか行えないことを根本的な限界として指摘する。すなわち、既存手法はタスク全体に対して一度だけ最適な LLM を選ぶが、マルチステップのワークフローでは各ステップで「どの LLM が最適か」が、進行中のタスク進捗、残タスクの難易度、コスト効率要件という動的・状態依存的な要因によって変わり続けるため、静的な決定は適応できない。

ProgRouter はこの問題に対し、以下のような構成要素を提案している。

- **マルチビュー進捗スコアラー**: ワークフロー全体の成否を粗く捉えるアウトカムレジームと、サブタスクの完了度・進捗トレンド・ワークフロー状態の質といったきめ細かな信号を組み合わせて、タスク進捗を評価する。
- **デュアルパス進捗予測器とアダプティブ・メタゲーティング機構**: 候補となる各ルーティング先 LLM について、それを選んだ場合に得られる「進捗ゲイン」を推定する。
- **オンラインのステップ単位ルーティング決定**: 進捗ゲイン、タスクの残り要求、時間・コスト予算のバランスを取りながら、各ステップでどのエージェントに処理を委ねるかを逐次決定する。

この設計が示す理論的含意は、資源配分の最適化問題が「静的な一括割当」ではなく「状態遷移に応じたフィードバック制御」として扱われるべきだという点である。進捗の推定精度が資源配分の質を直接左右するため、進捗評価そのものが制御システムの一部として組み込まれる必要がある。ただしこの知見は現在の LLM 技術・マルチエージェント構成に強く依存しており、技術基盤が変化すれば具体的な実装は変わり得る点も留意される。

## AI Native な設計への示唆

1. **一括判断からステップ単位の再評価への移行**: タスク開始時にすべての資源配分を決定するのではなく、各ステップで進捗・残難易度・予算消費を再評価し、必要に応じてエージェントや計算量の割当を更新する制御ループを組み込む。
2. **進捗推定を資源配分の一次情報として扱う**: 粗いアウトカム指標だけでなく、サブタスク完了度や進捗トレンドなど複数粒度の信号を統合し、進捗推定の精度自体をシステム設計の重要な構成要素とする。
3. **品質・コストのトレードオフを明示的な最適化対象にする**: 「最高品質のエージェントを常に使う」のではなく、進捗ゲインと時間・コスト予算の関係をモデル化し、予算制約下で品質を最大化する意思決定として資源配分を定式化する。
4. **状態依存ルーティングを前提としたアーキテクチャ**: マルチエージェントシステムでは、各ステップで最適なエージェントが変わり得ることを前提に、ルーティング機構を固定的なパイプラインではなく動的なゲーティング・メタ制御として実装する。
5. **進捗の誤推定リスクへの備え**: 進捗推定自体が不確実性を伴う推論結果であるため、推定誤差が資源配分の誤りに波及する可能性を考慮し、推定の信頼度や複数視点の併用によって頑健性を確保する設計が求められる。
