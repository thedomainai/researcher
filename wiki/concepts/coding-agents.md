# コーディングエージェントのアーキテクチャ（Coding Agent Architecture）

## 概要

コーディングエージェントとは、LLMをエージェントハーネス（制御ループ）で包み、コード生成・編集タスクにおいてモデル単体を大きく超える性能を実現するシステムである。Claude Code、Codex CLIなどがこのカテゴリに属する。

重要な洞察は、**最近のLLMの実用的進歩の多くはモデル自体の改善ではなく、モデルの「使い方」のシステム設計にある**という点である。同じモデルでも、ハーネスの質によって体感的な能力が大きく異なる。

## 3層モデル

Sebastian Raschkaによる整理：

- **LLM**: 生のnext-tokenモデル（エンジン）
- **推論モデル**: 中間的な推論トレースを出力するよう訓練されたLLM（強化エンジン）
- **エージェント**: モデルとツール・メモリ・環境フィードバックを組み合わせた制御ループ

エンジンの性能差が縮まる中（GPT-5.4, Opus 4.6, GLM-5が同等水準）、ハーネスが差別化要因になっている。

## 6つの構成要素

### 1. ライブリポジトリコンテキスト

Gitブランチ、プロジェクト構造、ドキュメント（AGENTS.md、README）などの「安定的な事実」をエージェントが作業前に収集する。「テストを直して」という指示はコンテキストなしでは解釈不能。

### 2. プロンプト形状とキャッシュ再利用

ワークスペースサマリーなどの安定部分をプレフィックスキャッシュとして再利用し、毎回の再処理を避ける。

### 3. 構造化ツール・検証・権限

ツール呼び出しの定義、入力検証、実行権限の管理。ファイル編集、コマンド実行、検索などを構造化されたインターフェースで提供。

### 4. コンテキスト削減と出力管理

長いセッションでコンテキストウィンドウが溢れないよう、履歴の要約・圧縮を行う。

### 5. トランスクリプト・メモリ・再開

セッション間での状態保持。過去の作業の記録と再開を可能にする。

### 6. 委任と限定サブエージェント

複雑なタスクを小さなサブタスクに分割し、制約付きのサブエージェントに委任する。

## AI nativeな組織設計への示唆

コーディングエージェントのアーキテクチャは、AI nativeな組織のマイクロコスム（縮図）と見なせる：

- **コンテキスト管理** → 組織におけるナレッジマネジメント
- **ツール統合** → 組織のシステム連携
- **委任とサブエージェント** → 組織における権限委譲と分業
- **メモリと再開** → 組織の制度的記憶
